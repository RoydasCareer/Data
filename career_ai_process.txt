Career AI 프로젝트 진행 정리
================================

1. 내가 원하는 목표
-------------------
내 목표는 회사 채용 홈페이지 주소를 입력하면, 그 사이트에서 채용 공고를 자동으로 수집하고,
내 프로필과 비교해 잘 맞는지/가능성이 있는지 판단한 뒤 점수화하는 프로그램을 만드는 것이다.

핵심 기능은 아래와 같다.
- 채용 공고 수집
- 공고 상세 내용 추출
- 내 프로필과 비교
- 적합도 점수 계산
- 공고에서 내가 어필할 수 있는 강점/특장점 추출
- 70점 이상 또는 AI가 좋게 판단한 공고는 따로 보관(shortlist)
- 기업 정보도 주기적으로 수집해서 주간 보고서 생성
- 나중에 로컬 LLM을 붙여 더 똑똑하게 분석

지원 자동화(자동 지원, 자동 메일 발송)는 현재 제외하고,
분석과 정리, 보관, 리포트 생성 중심으로 만들고 싶었다.

2. 내가 원하는 최종 구조
------------------------
전체 흐름은 다음처럼 구상했다.

회사 채용 URL 입력
→ 채용 공고 수집
→ 공고 상세 수집
→ 공고 정규화
→ 사용자 프로필과 비교
→ 점수 계산
→ 강점/어필 포인트 추출
→ shortlist 저장
→ 주간 기업 리포트 생성
→ Telegram/이메일로 알림 또는 파일 저장

3. 네가 제시한 방법과 구조
-------------------------
너는 처음에 이 시스템을 "개인 AI 리크루팅/채용 인텔리전스 플랫폼"으로 설계하는 것이 좋다고 했다.

추천 구조는 대략 다음과 같았다.
- 수집기(Crawler)
- 정규화기(Normalizer)
- 분석기(Analyzer)
- 저장소(Database)
- 보고서 생성기(Report Generator)
- 알림(Notifier)
- 나중에 로컬 LLM 연결

초기에는 하나의 큰 프로젝트 안에서 모듈을 나누는 모놀리식 구조가 가장 유지보수하기 좋다고 설명했다.
즉, 처음부터 마이크로서비스로 쪼개지 말고:
- Python
- Playwright
- SQLite
- FastAPI
- APScheduler
- 나중에 Ollama/LangGraph
방식으로 가는 것이 좋다고 제안했다.

4. 네가 제안한 핵심 설계 포인트
------------------------------
- 크롤링은 Playwright로 처리
- 정적 HTML만 requests/BeautifulSoup로 처리할 수도 있지만, 대부분 채용 사이트는 동적 렌더링이라 Playwright가 유리
- 공고마다 구조가 다르므로 공통 JSON 스키마로 정규화
- 내 프로필도 JSON으로 구조화
- 점수는 규칙 기반 + 나중에 LLM 기반으로 확장
- shortlist는 70점 이상 또는 AI가 판단해 가능성이 높다고 본 공고를 저장
- 기업 정보는 주간 단위로 별도 수집해서 리포트로 남김
- 나중에 로컬 LLM을 붙여 합격 가능성, 강점, 커리어 포인트를 더 잘 뽑아내는 구조로 확장

5. 우리가 실제로 시도한 것
------------------------
(1) 개발 환경 문제 해결
- Python venv 생성 중 ensurepip에서 막힘
- venv가 깨진 상태로 남아서 Permission denied 오류 발생
- 깨진 venv를 삭제하고 다시 생성
- PowerShell 실행 정책 때문에 Activate.ps1 문제를 확인
- 결국 가상환경 생성 및 활성화 성공

(2) 프로젝트 기본 구조 생성
- FastAPI 서버
- SQLite DB
- 채용 공고 크롤러
- 기업 정보 크롤러
- 점수 계산기
- 강점 추출기
- 주간 보고서 생성기
- Telegram 알림 구조
- 로컬 LLM 연결은 나중에 붙이기로 함

(3) ZIP 파일 생성
- 전체 프로젝트 구조를 ZIP으로 만들었고 다운로드 가능하게 제공받음
- 이후 다시 수정된 버전의 ZIP도 만들었음

(4) DB 생성 문제 해결
- DATABASE_URL이 None이라 create_db.py가 실패
- .env 또는 기본값 설정이 없어서 생긴 문제였음
- DATABASE_URL=sqlite:///career.db 로 수정/설명
- 이후 DB 생성 성공

(5) 채용 사이트 크롤러 개발
- 먼저 requests/BeautifulSoup 방식으로 시도
- Toss 같은 SPA 사이트에서 soup.title이 None이 되는 오류 발생
- Playwright 기반으로 전환
- 리스트 페이지 수집, 상세 페이지 수집을 시도
- 공고 링크를 긁는 구조를 만들었음

(6) 상세 공고 수집
- 상세 페이지에서 제목, 본문, 스킬, 경력 조건을 추출하는 함수 작성
- soup.title이 없는 경우를 대비해 h1, og:title, meta description을 보도록 수정

(7) DB 스키마 불일치 해결
- career.db의 기존 테이블 구조에 url 컬럼이 없어서 no such column: jobs.url 오류 발생
- DB 파일 삭제 후 재생성하여 해결
- 그 뒤 run_crawl.py 실행 성공

(8) 회사별 채용 사이트 추가
- company_sources.py에 회사 이름과 리스트 URL을 적는 구조를 제안/구현
- Hyundai, Kia, Hyundai AutoEver, Hyundai Mobis 등을 넣어 테스트
- 일부 회사는 list jobs가 0으로 나왔고, 일부는 수집 성공

(9) shortlist 기능 추가
- score가 70점 이상이거나, AI 판단상 잘 맞는 공고를 따로 저장하는 기능을 넣음
- current structure상 shortlist 테이블에 저장
- 나중을 위해 JD를 따로 보관할 수 있게 하려는 의도를 반영

6. 현재까지 도달한 상태
-----------------------
현재까지의 진행 상태는 다음과 같다.

성공한 것:
- Python 가상환경 생성 및 활성화
- 필요한 패키지 설치
- Playwright 설치
- SQLite DB 생성
- 일부 회사 채용 사이트 수집
- 공고 상세 페이지 수집
- 점수 계산
- shortlist 저장
- 주간 리포트 파일 생성
- FastAPI 서버 실행
- /docs 접속 성공

막혀 있거나 개선이 필요한 것:
- 회사별로 공고 구조가 달라서 공고 링크 필터링이 완벽하지 않음
- 일부 회사는 list jobs가 0으로 나옴
- 페이지네이션이 회사별로 달라서 더 세밀한 처리 필요
- job_link_keyword를 어떤 값으로 넣어야 하는지 회사별로 판단해야 함
- 현재는 LLM 없이 규칙 기반 점수만 사용
- 회사별 selector/파서 최적화가 더 필요함

7. 현재까지 만든 핵심 파일/구조
-------------------------------
프로젝트 흐름상 핵심 파일은 다음과 같았다.
- main.py: FastAPI 앱 진입점
- create_db.py: DB 생성
- run_crawl.py: 전체 크롤링 실행
- user_profile.json: 내 프로필 저장
- app/crawler/company_sources.py: 회사 채용 사이트 목록
- app/crawler/job_list_crawler.py: 채용 목록 수집
- app/crawler/job_detail_crawler.py: 상세 JD 수집
- app/analyzer/matching_engine.py: 점수 계산 및 shortlist 판단
- app/storage/db.py: DB 연결
- app/storage/models.py: Job/Shortlist/CompanySnapshot 모델
- app/storage/repository.py: DB 저장/조회
- app/report/weekly_report.py: 주간 리포트 생성
- app/services/orchestrator.py: 전체 자동화 흐름
- app/api/routes.py: FastAPI 엔드포인트

8. 내가 이해한 현재 핵심 개념
---------------------------
- DATABASE_URL은 회사 채용 사이트 URL이 아니라 DB 저장 위치 설정이다.
- 채용 사이트 주소는 company_sources.py에 넣는다.
- job_link_keyword는 공고 링크에 반복적으로 들어가는 문자열 힌트다.
- 예: /apply/, /jobs/, /recruit/ 같은 식으로 회사별로 달라질 수 있다.
- 현재 크롤링은 모든 사이트에 완벽히 맞는 만능 방식이 아니라, 회사별로 조정이 필요하다.
- shortlist는 미래를 위한 JD 아카이브 역할도 한다.

9. 앞으로 이어서 해야 할 것
-------------------------
다음 단계에서 보완할 핵심 항목은 아래와 같다.
- 회사별 채용 사이트 전용 크롤러 보강
- 페이지네이션(다음 페이지) 처리 개선
- 공고 링크 필터링 정교화
- JD 중복 제거 강화
- shortlist UI 또는 조회 기능 개선
- 주간 기업 리포트 내용을 더 풍부하게 만들기
- 나중에 로컬 LLM 연결
- 점수를 단순 키워드가 아닌 의미 기반으로 향상

10. 한 줄 요약
-------------
나는 "회사 채용 사이트를 넣으면 자동으로 공고를 수집하고, 나와 맞는 공고를 점수화해서 shortlist와 주간 리포트로 남기는 개인용 채용 인텔리전스 시스템"을 만들고 있고,
현재는 기본 수집/저장/점수화/shortlist/리포트까지 일부 구현했고,
회사별 크롤러 정교화와 페이지네이션 개선이 다음 단계다.
