## ⚠️ MANDATORY: RULE.md COMPLIANCE
================================================================================
You MUST strictly follow RULE.md guidelines throughout this project:

1. THINK BEFORE CODING
   - State all assumptions explicitly before implementation
   - If uncertain, ASK before proceeding - never guess silently
   - Present multiple interpretations if they exist - don't pick one silently
   - If a simpler approach exists, propose it and push back when warranted
   - If anything is unclear, STOP and name what's confusing

2. SIMPLICITY FIRST
   - Write MINIMUM code that solves the problem - nothing speculative
   - NO features beyond what was explicitly requested
   - NO abstractions for single-use code
   - NO "flexibility" or "configurability" that wasn't requested
   - NO error handling for impossible scenarios
   - If code could be 50 lines instead of 200, REWRITE it
   - Ask: "Would a senior engineer say this is overcomplicated?" If yes, simplify

3. SURGICAL CHANGES
   - Touch ONLY what you must - clean up only your own mess
   - When editing existing code:
     * Don't "improve" adjacent code, comments, or formatting
     * Don't refactor things that aren't broken
     * Match existing style, even if you'd do it differently
     * If you notice unrelated dead code, mention it - DON'T delete it
   - When your changes create orphans:
     * Remove imports/variables/functions that YOUR changes made unused
     * Don't remove pre-existing dead code unless asked
   - Test: Every changed line should trace directly to the user's request

4. GOAL-DRIVEN EXECUTION
   - Transform tasks into VERIFIABLE goals with success criteria
   - For multi-step tasks, state a brief plan:
     1. [Step] → verify: [check]
     2. [Step] → verify: [check]
     3. [Step] → verify: [check]
   - Strong success criteria enable independent looping; weak criteria require constant clarification

## 📋 PROJECT OVERVIEW
================================================================================
Project Name: HiSponsor
Purpose: A bilingual (Korean/English) blog platform that aggregates visa sponsorship job postings, visa/country information, and resume templates for international job seekers.

Target Users:
- Korean speakers seeking overseas employment with visa sponsorship
- English speakers seeking similar opportunities
- Non-technical site administrators who need to manage content via Google Sheets

Core Features:
1. Home: Introduction, feature overview, feedback request
2. Info: Visa and country-specific information posts with comments
3. Jobs: AI/automation-collected job postings from external sites
4. Templet: Resume/CV template marketplace (MVP: external payment links)
5. Contact: Inquiry form with auto-response + Telegram notification
6. Language Toggle: KO/EN button (top-right) for instant language switching

================================================================================
## 🛠️ TECHNICAL STACK (FREE-TIER FIRST)
================================================================================
Frontend:
- Astro (static site generation) with @astrojs/cloudflare adapter
- Cloudflare Pages for hosting (free, unlimited bandwidth)
- Client-side language toggle using localStorage (no SSR i18n complexity)

Backend/Data:
- Google Sheets as CMS/database (single spreadsheet, multiple tabs)
- gspread + google-auth for Python/Node.js Sheets access
- NO traditional backend server - all data operations via Sheets API

Automation:
- Make.com (free tier: 1,000 ops/month) for workflow orchestration
- Google Gemini API (free tier: 15 RPM, 1.5M tokens/month) for AI processing
- Giscus (GitHub Issues-based) for comments (free, no backend)

Forms/Notifications:
- Formspree (free tier) for Contact form handling
- Telegram Bot API for admin notifications

Development:
- GitHub for version control + GitHub Actions for automated deployments
- All code must be non-programmer maintainable via documentation

================================================================================
## 🏗️ ARCHITECTURE OVERVIEW
================================================================================
Data Flow:
[External Job Sites] 
       ↓ (Make.com: RSS/API/HTTP)
[Google Sheets: raw_queue] 
       ↓ (Make.com + Gemini AI: extract/structure)
[Google Sheets: processed_jobs] 
       ↓ (Make.com + Gemini AI: translate KO↔EN)
[Google Sheets: translated] 
       ↓ (Make.com + Gemini AI: verify quality/legal compliance)
[Google Sheets: validated] 
       ↓ (Admin approval via Telegram → Sheets update)
[Google Sheets: approved] 
       ↓ (Make.com: GitHub API commit)
[GitHub: hisponsor-blog repo] 
       ↓ (Cloudflare Pages: auto-deploy on push)
[Live Site: hisponsor.pages.dev]

Content Management:
- ALL content (posts, jobs, templates, config) managed via Google Sheets
- Non-programmer edits Sheets → next build/trigger reflects changes
- NO code editing required for content updates

Language Handling:
- Single post contains both KO and EN fields (title_ko/title_en, body_ko/body_en)
- Client-side toggle shows/hides elements based on [lang] attribute + localStorage
- Fallback: if EN field empty, display KO field with "[EN translation pending]" note

## 💬 CODE COMMENTING REQUIREMENTS (BILINGUAL + DETAILED)
================================================================================
EVERY code file MUST include comments in BOTH Korean AND English:

Format:
// [KO] 한국어 설명: 이 함수는 ~을 합니다.
// [EN] English explanation: This function does ~.

Rules:
1. File headers: Explain purpose, author, last modified, dependencies
2. Function headers: Explain input, output, side effects, edge cases
3. Complex logic: Explain WHY, not just WHAT (with both languages)
4. Configuration values: Explain valid ranges, defaults, where to change
5. API calls: Document endpoint, auth method, rate limits, error handling
6. User-facing strings: Note if translatable, character limits, context
