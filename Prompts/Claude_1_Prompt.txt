Before writing a single line of code, you MUST read and fully comply with
the project's RULE.md file located in the root of the repository.
RULE.md is the single source of truth for all coding standards.

Summary of RULE.md requirements (do NOT skip these):
  • You are an expert TypeScript / Next.js developer.
  • MINIMAL  — Write the absolute minimum code needed. No over-engineering.
  • SELF-DOCUMENTING — Use precise naming: verbs for functions, nouns for variables.
                       Single-responsibility components. Obvious data flow.
  • TYPE-EXACT — Strict TypeScript types. Zero use of `any`. Ever.
  • SECURE    — Built-in security for auth and data handling at all times.
  • PERFORMANT — Always follow Next.js optimization guides (ISR, SSR, lazy loading).
  • PLAN FIRST — Before coding, write a <thinking> block:
      1. Identify the core requirement.
      2. Consider 3 implementation approaches.
      3. Choose the simplest that fully meets the requirement.
      4. Verify: Can this be split into smaller functions?
                 Are there unnecessary abstractions?
                 Will a junior developer (or non-programmer) understand this?

  SECTION 6 — INTERNATIONALIZATION (KO / EN)
═══════════════════════════════════════════════════════════════════════════════

  Library : next-intl
  Install : npm install next-intl

  URL pattern:
    /ko          → Korean Home
    /en          → English Home
    /ko/jobs     → Korean Jobs
    /en/jobs     → English Jobs

  Locale detection:
    Default locale : ko
    Fallback       : en (if translation key missing)
    Cookie-based   : yes (remember user preference)

  File structure:
    messages/ko.json   ← All Korean UI strings
    messages/en.json   ← All English UI strings

  LangSwitch component (top-right of NavBar):
    - Shows current locale flag + code (🇰🇷 KO or 🇺🇸 EN)
    - On click: switches locale, preserves current path
    - Example: /ko/jobs → click EN → /en/jobs

  Translation key naming convention:
    {page}.{section}.{element}
    Example: "jobs.filter.visaLabel": "비자 스폰서"

  Database bilingual fields:
    All content tables store both _ko and _en columns.
    If _en is empty, fallback to _ko (no blank pages).

  SECTION 8 — SUPABASE SETUP (SQL — Run in Order)
═══════════════════════════════════════════════════════════════════════════════

  Run these SQL statements in Supabase → SQL Editor → New Query:

  ── STEP 1: Create all tables ───────────────────────────────────

  -- 채용공고 테이블 / Job listings table
  CREATE TABLE jobs (
    id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    title       TEXT NOT NULL,
    company     TEXT NOT NULL,
    location    TEXT,
    country     TEXT,
    category    TEXT,
    employment  TEXT,
    description TEXT,
    visa        BOOLEAN DEFAULT false,
    salary      TEXT,
    apply_url   TEXT,
    slug        TEXT UNIQUE NOT NULL,
    source      TEXT,
    is_active   BOOLEAN DEFAULT true,
    created_at  TIMESTAMPTZ DEFAULT NOW()
  );

  -- 정보 게시물 테이블 / Info posts table (bilingual)
  CREATE TABLE posts (
    id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    title_ko    TEXT NOT NULL,
    title_en    TEXT,
    content_ko  TEXT,
    content_en  TEXT,
    excerpt_ko  TEXT,
    excerpt_en  TEXT,
    category    TEXT,
    country     TEXT,
    slug        TEXT UNIQUE NOT NULL,
    is_ai_gen   BOOLEAN DEFAULT false,
    is_active   BOOLEAN DEFAULT true,
    created_at  TIMESTAMPTZ DEFAULT NOW()
  );

  -- 템플릿 테이블 / Templates table
  CREATE TABLE templates (
    id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    title_ko        TEXT,
    title_en        TEXT,
    description_ko  TEXT,
    description_en  TEXT,
    price           INTEGER DEFAULT 0,
    currency        TEXT DEFAULT 'KRW',
    file_url        TEXT,
    preview_urls    TEXT[],
    platform        TEXT[],
    seller_id       UUID REFERENCES auth.users,
    downloads       INTEGER DEFAULT 0,
    is_active       BOOLEAN DEFAULT true,
    created_at      TIMESTAMPTZ DEFAULT NOW()
  );

  -- 리뷰 테이블 / Reviews table
  CREATE TABLE reviews (
    id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    template_id UUID REFERENCES templates ON DELETE CASCADE,
    user_id     UUID REFERENCES auth.users,
    rating      INTEGER CHECK (rating BETWEEN 1 AND 5),
    comment     TEXT,
    created_at  TIMESTAMPTZ DEFAULT NOW()
  );

  -- 문의 테이블 / Contact submissions table
  CREATE TABLE contacts (
    id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    name        TEXT NOT NULL,
    email       TEXT NOT NULL,
    subject     TEXT,
    message     TEXT NOT NULL,
    type        TEXT,
    status      TEXT DEFAULT 'new',
    created_at  TIMESTAMPTZ DEFAULT NOW()
  );

  ── STEP 2: Enable Row Level Security ───────────────────────────

  ALTER TABLE jobs      ENABLE ROW LEVEL SECURITY;
  ALTER TABLE posts     ENABLE ROW LEVEL SECURITY;
  ALTER TABLE templates ENABLE ROW LEVEL SECURITY;
  ALTER TABLE reviews   ENABLE ROW LEVEL SECURITY;
  ALTER TABLE contacts  ENABLE ROW LEVEL SECURITY;

  ── STEP 3: Set access policies ─────────────────────────────────

  -- 누구나 읽기 허용 / Allow public read
  CREATE POLICY "public_read_jobs"      ON jobs      FOR SELECT USING (true);
  CREATE POLICY "public_read_posts"     ON posts     FOR SELECT USING (true);
  CREATE POLICY "public_read_templates" ON templates FOR SELECT USING (true);
  CREATE POLICY "public_read_reviews"   ON reviews   FOR SELECT USING (true);

  -- 문의 등록은 누구나 / Allow anyone to submit contact
  CREATE POLICY "public_insert_contacts" ON contacts FOR INSERT WITH CHECK (true);

  -- 리뷰는 로그인 사용자만 / Only logged-in users can review
  CREATE POLICY "auth_insert_reviews" ON reviews FOR INSERT
    WITH CHECK (auth.uid() = user_id);

  SECTION 12 — GENERAL CODING RULES FOR THIS PROJECT
═══════════════════════════════════════════════════════════════════════════════

  1. Always follow RULE.md first and above all.

  2. EVERY component must have:
     - JSDoc comment block above (bilingual: Korean + English)
     - Prop types defined in src/types/index.ts (no inline types)
     - A readable default export name matching the filename

  3. All user-facing strings MUST come from messages/[locale].json.
     Hard-coded strings in JSX are forbidden.

  4. Supabase queries belong in:
     - lib/supabase.ts (browser client, public data)
     - lib/supabase-server.ts (server components, protected data)
     Never write raw Supabase calls inside page or component files.

  5. Images: always use next/image with explicit width and height.
     All images must have alt text (translated via t() function).

  6. Error handling: every async function must handle errors gracefully.
     Show user-friendly error messages (translated), not raw error objects.

  7. Mobile-first design:
     - Default Tailwind classes = mobile layout
     - md: and lg: prefixes = tablet and desktop overrides
     - Minimum tap target: 44×44px for all interactive elements

  8. Color usage: ONLY use brand colors defined in tailwind.config.ts.
     No raw hex codes in JSX. Use: text-coral, bg-pale, border-brand, etc.

  9. File naming:
     - Components: PascalCase  (JobCard.tsx)
     - Utilities:  camelCase   (formatDate.ts)
     - Routes:     kebab-case  (page.tsx inside [slug] folder)

  10. Git commit messages:
      Format: [emoji] [scope]: [description]
      Examples:
        ✨ feat(jobs): add visa filter to job list
        🐛 fix(nav): lang switch not preserving path
        📝 docs: update README setup instructions
        🤖 auto: weekly AI post generation
