당신은 시니어 프론트엔드/풀스택 엔지니어이자 프로덕트 설계자입니다.
내가 만들고 싶은 서비스는 “지구본 기반 여행 기록 웹사이트”입니다.
아래 요구사항을 정확히 이해하고, 누락 없이 로컬에서 실행 가능한 수준으로 설계 및 구현해 주세요.

# 1. 프로젝트 목표

여행 기록 웹사이트를 만들고 싶습니다.

중요한 시각적 요구사항:
- 구글 어스처럼 “지구본 형태”로 보여야 합니다.
- 하지만 지구 표면은 위성사진 같은 실사 느낌이 아니라,
  구글맵 / 네이버지도 / 카카오맵의 기본 지도처럼
  “평면 2D 지도 스타일”이 지구 표면에 입혀진 느낌이어야 합니다.
- 즉, “실사형 3D 지구”가 아니라 “지도형 3D 지구”입니다.

# 2. 최우선 개발 방향

- 일단 로컬 환경에서 완전 실행 가능한 웹 프로젝트로 만들어 주세요.
- 배포/호스팅은 나중에 할 예정이므로 우선순위가 아닙니다.
- AI가 가능한 한 많은 부분을 자동으로 구현할 수 있도록 진행해 주세요.
- 나는 가능한 한 적게 개입하고 싶기 때문에, 스스로 폴더 구조, 기술 선택, 기본 UI/UX, 샘플 데이터, 실행 방법까지 제안하고 구현해 주세요.
- 단, 각 단계에서 왜 그렇게 설계했는지도 짧게 설명해 주세요.

# 3. 기술적 선호 및 제약

반드시 고려할 것:
- 웹사이트 형태로 구현
- HTML, CSS 활용 비중을 높게
- JavaScript는 필요 시 사용
- 추후 네이버 블로그, 티스토리, GitHub Pages 또는 iframe 기반 임베딩 가능성을 고려한 구조
- 가능하면 프론트엔드 단독 또는 로컬 JSON/브라우저 저장소 기반으로 먼저 구현
- 초기 버전에서는 서버 없이도 최대한 동작 가능하게 설계
- 나중에 백엔드/API/DB를 붙이기 쉬운 구조로 컴포넌트화

기술 제안 시 아래 우선순위를 고려:
1. 유지보수 쉬움
2. 로컬 실행 쉬움
3. 임베딩 확장성
4. 시각적 완성도

# 4. 반드시 필요한 핵심 기능

## 4-1. 지구본 지도 표시
- 3D 지구본 UI가 있어야 함
- 지구 표면은 “실사 위성 이미지”가 아니라 “2D 지도 스타일”
- 회전/확대/축소 가능
- 여행 지역 마커를 표시 가능
- 마커 클릭 시 해당 지역의 상세 정보 및 사진 라이브러리 표시

## 4-2. 지역 표시 기능
- 사용자가 직접 지역명을 입력해서 추가 가능
- 가능하면 좌표(위도/경도)도 저장
- 사진의 위치 정보(EXIF GPS)가 있으면 해당 정보를 기반으로 자동 지역 연결 가능
- 지역 데이터 예시:
  - 지역명
  - 국가
  - 위도/경도
  - 방문 날짜
  - 메모
  - 대표 사진

## 4-3. 사진 라이브러리 기능
- 사용자가 사진 업로드 가능
- 여러 장 다중 선택 가능
- 삭제 가능
- 사진에 위치 정보가 있으면 자동으로 해당 지역에 분류 저장
- 위치 정보가 없으면 사용자가 직접 지역 지정 가능
- 지역 마커를 클릭하면 그 지역의 사진 라이브러리/뷰어가 열려야 함
- 라이브러리 UI는 최소한 다음 기능 포함:
  - 썸네일 목록
  - 큰 사진 보기
  - 이전/다음 이동
  - 사진 삭제
  - 지역 재지정

## 4-4. 이동 경로 기능
- 사용자가 출발지, 도착지, 이동수단을 설정 가능
- 이동수단 예시:
  - 비행기
  - 자동차
  - 기차
  - 버스
  - 자가용
  - 자전거
  - 도보
- 예:
  - 출발: 인천공항
  - 도착: 태국 방콕 수완나품 공항
  - 이동수단: 비행기
  - 항공사/메모: 비엣젯

## 4-5. 경로 시각화 기능
- 3D 지구본 위에 출발지와 도착지를 잇는 경로를 표시
- 특히 비행기 이동은 지구 곡면을 따라가는 “곡선 아크 형태”로 보이게
- 경로 위에 교통수단 아이콘이 표시되게
- 예: 비행기 경로라면 비행기 아이콘이 출발지 → 도착지 방향으로 반복적/은은하게 움직이게
- 애니메이션은 눈에 거슬리지 않도록 부드럽고 과하지 않게
- 자동차/기차/버스/도보 등도 아이콘 또는 선 스타일로 구분 가능하게

# 5. UX/UI 요구사항

- 전체적으로 직관적이고 감성적인 여행 기록 서비스 느낌
- 하지만 과도하게 화려하지 않고 깔끔한 UI
- 최소 화면 구성:
  1. 지구본 메인 뷰
  2. 지역/사진/경로를 관리하는 사이드 패널 또는 하단 패널
  3. 사진 라이브러리 모달 또는 슬라이드 패널
- 반응형이면 좋지만, 초기 버전은 데스크톱 우선이어도 괜찮음
- 다크 테마 또는 지도와 어울리는 모던한 테마 제안 가능

# 6. 데이터 구조 설계도 함께 해 주세요

초기 버전은 서버 없이도 동작 가능하도록 아래 데이터를 로컬 상태 또는 JSON으로 관리해 주세요.
예시 엔티티를 먼저 설계해 주세요:
- places
- photos
- routes
- vehicles or transportTypes

각 엔티티에 필요한 필드를 제안하고,
샘플 JSON도 같이 만들어 주세요.

# 7. 구현 우선순위

아래 순서로 단계적으로 구현해 주세요.

1단계. 프로젝트 구조 설계
- 파일 구조 제안
- 사용 라이브러리 선정 이유 설명
- 로컬 실행 방법 설명

2단계. 지구본 기본 렌더링
- 2D 지도 느낌의 지구본 구현
- 회전/줌/기본 마커 표시

3단계. 지역 CRUD
- 지역 추가/수정/삭제
- 마커와 데이터 연결

4단계. 사진 라이브러리
- 사진 업로드/삭제
- 다중 선택
- 지역별 연결
- 지역 클릭 시 사진 뷰어 열기

5단계. EXIF 위치 정보 처리
- 사진 GPS 정보 읽기
- 가능하면 자동 지역 분류
- 실패 시 수동 지정 UX 제공

6단계. 이동 경로 기능
- 출발지/도착지/이동수단 입력
- 경로 데이터 저장
- 지구본에 곡선/선 표시

7단계. 아이콘 애니메이션
- 비행기/자동차 등 아이콘이 경로를 따라 움직이게 구현
- 성능과 시인성 고려

8단계. 임베딩 대응
- 블로그/정적 호스팅 환경에서 동작 가능한 빌드 구조 제안
- iframe 임베딩 시 고려사항 정리

# 8. 산출물 요구사항

내가 원하는 출력 방식은 아래와 같습니다.

반드시 포함:
1. 전체 아키텍처 설명
2. 추천 기술 스택
3. 왜 그 스택이 적합한지 설명
4. 파일/폴더 구조
5. 각 단계별 구현 계획
6. 실제 실행 가능한 코드
7. 샘플 데이터
8. 로컬 실행 방법
9. 이후 확장 포인트
10. 임베딩 시 주의사항

중요:
- 추상적인 설명만 하지 말고 실제 코드까지 작성해 주세요.
- 한 번에 전부 너무 크게 내지 말고, 단계별로 파일 단위로 나눠서 주세요.
- 각 단계가 끝날 때마다 “다음 단계 진행 여부”를 물어보지 말고, 가능한 범위 내에서 계속 구현해 주세요.
- 즉, Autopilot 모드로 진행해 주세요.
- 단, 중요한 기술 선택이 여러 갈래로 나뉘는 경우에는 가장 추천하는 안으로 먼저 구현하고, 대안은 짧게만 설명해 주세요.

# 9. 개발 시 세부 요구사항

반드시 지켜 주세요:
- 코드 가독성이 좋아야 함
- 초보자도 로컬에서 실행 가능한 수준의 설명 필요
- 하드코딩을 최소화하고 구조화
- mock 데이터로도 바로 동작해야 함
- 나중에 실제 지도 API 또는 백엔드로 교체하기 쉬운 구조
- UI 텍스트는 한국어 기준으로 작성
- 주석은 꼭 필요한 곳에만 간결하게
- 라이브러리 선택 시 너무 무거운 조합은 피하고 이유 설명

# 10. 구현 시 기대하는 추천 방향

가능하면 아래와 같은 방향을 우선 검토해 주세요:
- 3D 지구본 렌더링: WebGL 기반 라이브러리
- 지도 타일 또는 2D 맵 스타일을 지구 표면에 적용하는 방식
- 지역 마커/아크 경로/애니메이션을 자연스럽게 처리 가능한 구성
- 사진 EXIF GPS 파싱 가능
- 정적 배포 및 임베딩 친화적인 구조

단, 최종 선택은 당신이 가장 현실적이고 구현 가능한 방향으로 결정해 주세요.

# 11. 최종 목표

최종적으로 나는 아래가 가능한 초기 MVP를 원합니다:
- 지구본이 보인다
- 내가 여행한 지역을 추가할 수 있다
- 사진을 올리고 지역별로 볼 수 있다
- 이동 경로를 그릴 수 있다
- 비행기 같은 아이콘이 경로를 따라 움직인다
- 로컬에서 실행된다
- 나중에 블로그/정적 페이지에 임베딩할 수 있다

이제 위 요구사항을 바탕으로,
“실제로 구현 가능한 MVP”를 목표로 프로젝트를 설계하고 코드까지 작성해 주세요.
가능하면 한 번에 끝까지 진행하되, 파일 단위로 구분해서 제시해 주세요.
